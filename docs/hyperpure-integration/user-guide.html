Sending Purchase Orders to Hyperpure

How to send an approved Purchase Order straight to Hyperpure from within Odoo, what the price review screen is telling you, how vendor status updates show up automatically afterwards, and how to keep vendor pricing up to date.

Audience Purchase managers and buyers working with Hyperpure orders Reading time ~6 minutes

1. What this does

Once a Purchase Order for Hyperpure is approved in Odoo, it can be sent to Hyperpure directly from the PO itself — no re-typing it into Hyperpure's own ordering system. Hyperpure double-checks the prices and quantities, places the order on their side, and then sends progress updates (dispatched, delivered, etc.) back into the same PO automatically as they happen.

This currently works for outlets under Hyperpure's Hyderabad (Telangana) GST entity, with three more GST entities (Bangalore, Mumbai, NCR) partly set up and pending further vendor-side setup.

2. Sending a Purchase Order to Hyperpure

  1. Approve the Purchase Order as usual.
  2. Click Send to Vendor on the PO. (This button only appears for vendors set up with a Hyperpure connection.)
  3. A review screen opens — see §3 for how to read it.
  4. If everything looks right, confirm to send. Hyperpure validates the order and places it; you'll see an acknowledgement message on the PO once that's done.
Delivery date and delivery slot Hyperpure decides the actual delivery date on their own side — it isn't something Odoo sends across. If you know the specific delivery window Hyperpure has assigned this order (e.g. "9 am – 11 am"), you can enter it in the PO's Delivery Slot field before sending. Leave it blank unless you're sure — a slot that doesn't match what Hyperpure would otherwise assign can get the whole order rejected.

3. Understanding the price review screen

Before anything is sent, you'll see a line-by-line comparison: the price currently on your Purchase Order next to Hyperpure's own reference price for that product. This is your chance to catch a mismatch before Hyperpure rejects the whole order for it.

  • Prices match — nothing to do, proceed to send.
  • Prices don't match — the line is flagged. A Purchase Manager can choose to accept Hyperpure's price for that specific line and resend, rather than the order failing outright.

If Hyperpure still rejects an order after sending, the message shown is Hyperpure's own plain-language explanation where available (e.g. "RE PAPER STRAWS 6MM: Price difference between actual price and price entered by user is less than lower threshold...") rather than a generic technical error — so you know exactly which product and why.

4. After sending: how status updates arrive

Once an order is placed, Hyperpure sends progress updates back automatically — you don't need to check their portal separately. These show up in two places on the PO:

  • The Vendor Orders summary field — the current status per vendor order reference (Placed, Dispatched, Delivered, Cancelled, or Partial if an order was split and its parts don't all agree yet).
  • The chatter (activity log) at the bottom of the PO — a note for every update Hyperpure sends, so you can see the full history, not just the latest state.
Sending a PO to Hyperpure is not the same as receiving stock These vendor status updates track what's happening on Hyperpure's side. They don't automatically create a stock receipt or a vendor bill — you still confirm the actual delivery in Odoo the normal way once goods arrive.

If Hyperpure needs to cancel their side of an order, use Request Cancellation on the PO (only available while the vendor order is still in Placed status and hasn't shipped) — this asks Hyperpure to cancel; the PO reflects their confirmation once it comes back.

5. Keeping vendor prices up to date

Hyperpure's agreed prices are periodic, not looked up fresh on every single order. To pull their latest prices into Odoo's own vendor pricelist:

  1. Open the vendor's contact record.
  2. Click Sync Vendor Prices (Purchase Managers only).
  3. Odoo checks the current live price for every product it has a Hyperpure mapping for, and shows it next to the price already on file.
  4. Click Apply to Vendor Pricelist to write the new prices in. Only the products that were successfully checked get updated — anything not yet mapped to a Hyperpure product code is simply left as-is and called out separately, it won't block the rest from updating.
This does not touch existing Purchase Orders Syncing prices updates the vendor pricelist that future orders will use. A PO that's already been created keeps its own price until someone edits it directly.

6. Common questions

Why can't I select an outlet for some of our locations?
Only outlets that have been mapped to Hyperpure's system can be selected on a PO. Not every Harleys location is mapped yet for every Hyperpure GST entity — check with IT/Purchase administration if a location you expect to see is missing.

Why did "Sync Vendor Prices" only update a few products?
Only products with a Hyperpure product code on file can be price-checked. Products without one yet are shown but left unchanged — this is expected while more products are still being mapped, not an error.

I sent an order and it's been a while with no status update — is that normal?
Status updates depend on Hyperpure actually sending them. If a PO has sat in "Submitted" for an unusually long time with no chatter activity, check with IT — there can be gaps in Hyperpure's own vendor catalogue setup that are still being resolved on their side.
